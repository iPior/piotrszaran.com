## Overview

NARF Form Handler is a custom WordPress plugin used by Ontario court organizations to process network access requests and track employee profiles and access changes. I built the conditional request form, server-verified review and submission workflow, dedicated database layer, and administrative tools for judiciary and ministry teams.

## What I Built

- I implemented request flows for new users, staff transfers, access changes, account enable/disable, and staff deletion, with cascading organization selections, role templates, address suggestions, and organization-specific access checklists.
- I built the Request details -> Review -> Complete workflow, including Microsoft 365 MSAL-based submitter auto-fill, server-side identity verification, administrator-managed submission eligibility, and retry-safe persistence.
- I modeled employee users, organization-bound profiles, and current access separately from historical requests, with lifecycle transitions and tracked edits to active profiles.
- I built the Submissions, Users, and Settings admin modules, including searchable records, profile detail and editing, access catalogs, role and division templates, and submission whitelist management.
- I implemented configurable email notifications and formatted templates, optional PDF attachments, protected requester PDF downloads, CSV export, and administrator print/save-as-PDF views.

## How It Works

- The `[narf_form]` shortcode renders a conditional form that adapts to the request type and ministry, division, branch, and section. A nonce-protected server check verifies the signed-in submitter against the submission whitelist before enabling request selection.
- Review validates the request without saving records or sending email. Final AJAX submission repeats authorization and validation, checks that the input and relevant context still match the reviewed request, and commits through a durable operation record before processing lifecycle updates and notifications.
- Procedural PHP and modular JavaScript integrate with WordPress hooks, while a custom `wpdb` connection stores requests, normalized organization and access data, profiles, and processing state in the separate `narf_form` database. Admin tools expose saved records and profile history; requester downloads and email attachments share the same saved-submission PDF renderer.

## Technical Highlights

- **Employee lifecycle modeling**: I separated historical submissions from current employee profiles and access, supporting transfers, access changes, and audited profile edits without rewriting the original requests.
- **Retry-safe submission processing**: I implemented durable idempotency, reviewed-request integrity checks, and post-save recovery through client polling and scheduled reconciliation, preventing duplicate submissions and avoiding automatic resends when a notification attempt has an uncertain outcome.
- **Organization-scoped authorization**: I enforced exact whitelist membership for server-verified submitter identities and validated selected access against the target organization's catalog, with missing or invalid whitelist configuration denying submissions.
