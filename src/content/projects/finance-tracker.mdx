## Overview

FinLens is a self-hosted personal finance tracker built for two household users. I built it as a private alternative to managing financial data in Excel, with a React dashboard, statement upload flow, manual transaction review, category management, a Postgres-backed API, and a read-only MCP server for future conversational finance queries.

## What I Built

- I built the React web application for reviewing household finances, including dashboard summaries, monthly filters, spending by category, top merchants, transaction lists, statement history, and empty/error/loading states.
- I implemented PDF statement uploads that extract transaction data, persist uploaded files privately, create statement records, and insert transactions into a review queue.
- I built the manual categorization workflow for transactions, including category creation, editing, favorites, colors, fallback handling, and review status updates.
- I implemented the Hono API, Better Auth integration, Drizzle schema, and Postgres persistence layer for users, sessions, statements, transactions, and categories.
- I added a read-only MCP server with finance tools for spending summaries, month comparisons, transaction search, category breakdowns, and merchant-level queries.

## How It Works

- Users sign in to a private finance dashboard, upload PDF statements, review extracted transactions, and manually categorize spending so household data stays accurate.
- The API validates requests, stores uploaded statements, parses transactions, and exposes dashboard, transaction, statement, and category endpoints backed by Drizzle and Postgres.
- Shared TypeScript packages centralize contracts, date/money helpers, database schema, and finance query logic so the web app, API, and MCP server use the same data model.

## Technical Highlights

- **Manual review over guessed categorization**: I intentionally kept categorization human-controlled because merchant names alone are not accurate enough for household finance decisions, especially for mixed purchases like grocery and household items from the same store.
- **Private finance stack with real data boundaries**: The app keeps personal financial data self-hosted, authenticated, and stored in Postgres, with uploaded statements separated from the public web surface.
- **MCP-ready finance query layer**: The MCP server exposes structured read-only tools over the same finance queries used by the app, giving the project a path toward a private chatbot interface without exposing the database directly.
